# App specification — v0.1

## Scope

A local Windows dashboard and Intel Mac export utility for casual Codex usage analysis. Default Codex directories, extra folders, compact import/export, live refresh, and offline HTML reports. Windows optionally keeps the dashboard running in the tray and provides a floating usage widget. Public MIT repository. No server account, transcript browser, model calls or cloud sync.

## UI

Dark charcoal surfaces, thin panel borders, mint highlights, line icons and a left navigation rail based on the supplied reference image. Native OS window chrome. Overview has global date/project/model/source filters, four headline cards, a switchable daily chart, highlights, and text equivalents. Usage & Cost adds token composition, model bars, prompt timing, agent breakdown and pricing coverage. Projects is a searchable table with filters and explicit group merging. Sources owns local folders, imports, exports and inclusion controls. Settings owns timezone, computer label, assumed Fast share and pricing catalog import.

Dates use the selected IANA timezone. All-time includes indexed history through today; custom ranges include the whole final local day. A filtered export saves exactly the selected dataset. HTML exports contain inline CSS/JS/data and require no server; filtering is frozen to the saved scope, while navigation and chart measure switches remain usable.

## Architecture

- Python parser, accounting modules and SQLite index shared by dashboard and exporter.
- TypeScript/Vite UI with Chart.js; a pywebview window uses Edge WebView2 on Windows or WKWebView on macOS.
- A loopback-only HTTP server serves bundled UI assets and a token-protected API. Native file dialogs run through the desktop bridge. The CLI uses the same engine without a browser.
- One indexing worker prevents concurrent mutations. Watchdog notifications and a periodic fallback find session appends; only complete JSONL lines are consumed. Offset, mtime, size and a suffix anchor support restarts and replacement detection.
- Raw transcript text is read for deterministic extraction, then discarded. SQLite stores compact facts and private checkpoints; timestamped metric records have indexes for date/project/model/source queries.
- One activity marker per local day tracks chat presence. Hourly metric buckets preserve session/model/source identity and exact edit confirmation cutoffs while reducing repeated dashboard scans of large histories.
- Source candidates are deduplicated by session ID plus metadata timestamp. Rolling byte-prefix fingerprints prove that a copy extends another; conflicting copies retain accepted history and show diagnostics. Verified parent trace replay and exact paginated boundaries are reconciled by the accounting core.
- Imports validate version, checksum, field allowlists and counts, then replace one exporter’s candidates in a transaction. A failure rolls back. Disabled-source preferences persist. Sources can be forgotten without editing original logs.

## Project grouping

`project_groups.py` owns stable project identities, alias resolution, the migration and merge/undo transactions. `project_memberships` maps original project IDs to a root group, and `session_projects` records each canonical segment's original identity. A `project_sessions` view resolves current names and membership independently of the project IDs in older metric rows. Dashboard aggregates, filters, options and their revision are read from one SQLite snapshot.

On upgrade, group labels are seeded from indexed metadata and existing aliases. A background migration decodes stored facts in bounded batches, committing session identities as its restart checkpoint. No logs or metric records are read/recalculated for merging. Ingestion, imports and projection rebuilds register identities through the same function. Original facts and transfer identities are preserved; local grouping remains in place through imports and rebuilds.

`merge_projects({sources, target})` queues and coalesces matching submissions. The worker validates all groups and rejects cycles within the transaction, updates group membership and flattened aliases atomically, and returns source/target names, operation ID, affected counts and completion time. A selected group may be the destination. `alias({source, target})` delegates to that operation for compatibility. `undo_project_merge({operation_id})` accepts only the latest persisted merge, restores its identities' previous groups and aliases, and consumes the undo record. Chats arriving after a merge follow their original identity when it is undone.

`project-merges.ts` owns checkbox selection, search, destination previews, operation feedback and undo controls. UI state survives background redraws; queued and running states disable submissions, and failures retain the draft for retry. Window and table scroll positions are restored.

## Summary image copying

Overview, Usage & Cost and Projects expose a copy icon beside Refresh. Dedicated frontend modules prepare an immutable minimal analytics snapshot, render a fixed 1200 × 720 Canvas PNG and coordinate clipboard/save feedback. They use applied response filters and inclusive `date_bounds` from the same query cutoff, keeping date drafts and asynchronous refreshes separate from the exported values. Token activity includes inactive calendar days and uses at most 180 summed bins. The renderer has no external assets or dependencies and keeps cost coverage, observed additions/removals and total, and partial-coverage notes visible. Demo images are labeled.

Project names default off; an immediate Settings switch includes only the selected group's retained name. Native preferences are atomically saved in `summary-image-preferences.json`, because desktop origins use ephemeral ports. Browser previews use local storage. Neither preference path touches pricing/projection or enters transfers. Account caches, computer/source labels, paths and conversations never enter the image snapshot. Sources, Accounts, read-only reports and exporter modes omit the action; the widget remains unchanged.

The native bridge alone handles `copy_summary_image({png_base64})` → `{status:"copied"}`, `save_summary_image({png_base64,filename})` → `{status:"saved"|"cancelled"}` and `summary_image_preferences({include_project_names?})` → `{include_project_names}`. PNG payloads are validated against the fixed dimensions, structure and a 2 MiB limit. WinForms' STA receives PNG and bitmap formats, retries busy clipboard writes at most five times and flushes persistent data before disposing resources. Closing and timed-out GUI callbacks cannot start late writes. Clipboard and Save dialogs run outside indexing and the HTTP API. Browser writes use a promise-backed PNG ClipboardItem directly from the click handler. Failures retain the generated PNG for an explicit save; success feedback lasts three seconds.

`qa_summary_images.mjs` checks rendering, filter/date concurrency, privacy, remembered names, clipboard failure and browser/native save flows. Desktop smoke checks verify both clipboard formats, actual WebView2 paste, cancellation, exact fallback bytes and persistence after app exit.

## Live account allowance

`codex_account.py` locates the installed Codex executable and uses `account_rpc.py` to launch an owned hidden stdio app-server, initialize it, read the account identity and call [account/rateLimits/read](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt). Current Codex reuses the existing sign-in without reading credentials, creates no chats and makes no inference calls. Each request has a 15-second deadline; reads terminate their child process on failure, completion or app shutdown. Only a non-reversible identity fingerprint reaches the cache; service account identifiers and credentials are not exposed in the UI or saved in analytics.

`claude_usage.py` reads Claude plan limits through the installed, unmodified Claude Code. `ClaudeUsage` is a `PollingCache` with a 300-second interval and backoff up to 30 minutes; `claude_usage_enabled` defaults off. Each check runs `claude -p /usage --output-format stream-json --verbose --no-session-persistence --safe-mode` with stdin closed, stdout capped at 1 MiB, a 30-second timeout that kills the process tree, a private working directory, and `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`/`CLAUDE_CODE_OAUTH_TOKEN` removed so Claude Code uses its own sign-in. The documented SDK `usage_report` is allowlisted to limit rows (`kind`, `group`, `percent`, `resets_at`, scope label, `severity`, `is_active`); message text, session costs, `extra_usage` and identity are dropped. Missing reports name the installed version and suggest `claude update`. `providers/allowances.read(..., live=)` adds the check state as `check` and uses whichever of the check and the status-line file is newer. Bridge actions: `refresh_claude_usage` and `claude_usage_settings({enabled})`. Demo and exporter modes never spawn Claude Code; readings are never persisted, reported or exported.

`usage_limits.py` has its own background worker and memory cache, with a 60-second interval, coalesced manual refresh and bounded retry backoff up to five minutes. It never waits for the SQLite/indexing queue. `usage_limits` reads the cache immediately, and `refresh_usage_limits` wakes the worker without blocking. `usage_limits_settings({enabled})` changes fetching immediately and queues preference persistence. Dashboard fetching defaults on; demo and exporter modes prohibit the provider even if that preference is enabled.

The multi-bucket map takes precedence over the legacy single bucket. Only returned windows are rendered; nullable fields remain unavailable. Remaining percentage is clamped `100 - usedPercent`. Connection failures retain last-known values with a stale marker; crossing a reset time never changes remaining percentage. Account changes clear both windows and last-success time before new limits are fetched.

Shared TypeScript allowance types and helpers drive the compact Overview limits row (`limits-row.ts`: one chip per enabled provider with its tightest window, linking to Accounts), the full Accounts cards and the optional widget section. Window names (`windowName`) and rounded-down whole percentages (`remainingPercent`) are shared by all three. Allowance ignores analytics filters. Widget `show_usage_remaining` defaults off and `usage_remaining_bucket` defaults to Codex, preserving prior metric selections. Additional buckets enable a selector. Cached status and countdowns update independently of dashboard editors. Reports and transfer snapshots exclude allowance; README documents the optional Codex network connection.

`burn_rates.py` tracks successful, generation-accepted allowance observations under each polling cache lock. Each window's `burn_rate` carries percentage points/hour. Estimates retain the reading at or before the five-minute cutoff, require at least 60 seconds between readings, and divide by the actual observation duration. Samples reset on identity/configuration transitions, decreasing counters, window reset/duration changes, missing counters and gaps over twice the source interval.

`local_token_burn.py` queries reconciled `records` for timestamped usage in the trailing 300 seconds, restricted to enabled folder sources, and divides the total by five minutes. Historical backfills do not create current bursts, duplicate/replayed usage uses existing reconciliation, and imported snapshots are excluded. No account attribution is inferred. The shared local estimate is composed into dashboard `UsageLimits.token_burn_rate` and the top-level Accounts response's `token_burn_rate`; individual account snapshots have only allowance rates. It is available immediately after indexing, with zero for an empty valid window, and follows the existing indexer cadence. Source errors and incomplete freshness set optional `partial` and `detail` fields instead of suppressing valid indexed usage. A ready source with a scan within 60 seconds, or recent indexed usage while scans are pending, permits an explicitly partial estimate when other coverage is incomplete. If every source is offline, or neither a fresh scan nor recent events exists, preserve the previous estimate as stale; without a previous estimate, report collecting (Waiting for indexing) for ready sources or unavailable for offline sources. This avoids inventing a fresh zero during long scans. Source-set changes invalidate the cached estimate. Queries use one SQLite snapshot and cache by second, source update time and data revision; UI reads do not create counter samples. Both rate types expose nullable `value`, `status` (`collecting`, `available`, `stale`, `unavailable`), `observed_seconds` and `updated_at`. No rate data is persisted or exported.

The Accounts page renders estimates through `burn-rate.ts`, with one shared local rate above the account cards and account-specific allowance rates inside them; the Overview limits row shows the local token and dollar rates compactly. Compact widget markup omits both. Accounts refresh updates the account caches and requests local indexing with `refresh_local: true` and existing job coalescing; the widget's existing refresh does not request indexing. Remote polling intervals remain unchanged, and token history is used only for account history and totals.

## Concurrent accounts

`accounts.py` manages stable connection IDs, labels and enabled states through `account_storage.py`. The registry is separate from SQLite. Current Codex always uses the main environment; added accounts run with a child-only `CODEX_HOME` under `account-profiles/<id>/`, enforced file credential storage and browser ChatGPT sign-in. On Windows, each profile has a protected inheritable DACL restricted to the current user's SID. Codex owns login and renewal; raw credentials never pass through the application bridge, logs, reports or transfers. Removing an added account invalidates its caches immediately, then signs out only that profile and removes its credential file.

`account_login.py` permits one browser flow, supports cancellation/reopening the browser and has a five-minute deadline. Existing account workers keep running. Reconnection stops that connection's old readers before starting sign-in and creates fresh caches afterward. `account_monitor.py` owns independent allowance/reset and history caches using `account_polling.py`: 60-second and five-minute polling respectively, bounded backoff, independent errors/freshness and coalesced manual refresh. Accounts do not share workers. Generation guards reject responses after identity changes, disabling or removal; shutdown cancels login, invalidates caches and terminates owned processes.

Bridge actions: `accounts`, `account_refresh({id?})`, `account_settings({id,label?,enabled?})`, `account_login_start({label?,id?})`, `account_login_status`, `account_login_cancel`, `account_login_open` and `account_remove({id})`. Existing allowance actions address Current Codex; the live-data preference applies globally. Dashboard and widget consume the same memory snapshots. No account caches are persisted or included in HTML/transfer exports. Demo/exporter modes prohibit providers and login.

`account_data.py` allowlists nullable service fields. `account/usage/read` snapshots replace previous summaries/buckets; zero is real usage, missing history remains unavailable and bucket dates are preserved. `rateLimitResetCredits.availableCount` is authoritative even with partial details. Explicit null expiration means no expiration; an absent expiration is unavailable. Expired timestamps wake allowance refresh once per reported credit/timestamp and never decrement the count locally. Unsupported endpoints degrade independently; reset redemption and expiry notifications are outside scope.

`views/accounts.ts`, `account-history.ts` and `account-credits.ts` render account cards, account-reported daily charts (30/90/all available), allowance, plan and dated banked resets. Existing project/cost/edit analytics retain their original scope. `widget-account-settings.ts` persists selected IDs/order and per-account buckets; `widget-accounts.ts` renders cached compact rows at 240 CSS pixels. A fixed toolbar sits above one scrolling area containing totals, accounts and local providers. Native geometry caps the displayed size to monitor working bounds while retaining the preferred height. Browser and native demo checks cover long labels, several accounts, small viewports and 100–200% scaling.

`account_groups.py` groups connections by confirmed private identity for both lifetime totals and presentation. Account snapshots retain all connections and expose `display_id` as a representative connection ID, without exposing account identity evidence. Enabled connections take priority, followed by Current Codex and registry order. The shared frontend account presentation helper preserves group order and selected aliases across the Accounts page, widget and widget picker. A collapsed Sign-in connections disclosure exposes controls for hidden connections without repeating usage. Widget reordering moves selected aliases as a group; unchecking removes the group's selections, checking adds the displayed connection, and bucket preferences remain keyed to the first selected connection. Identity loss or a Codex account switch recomputes presentation on the next account poll without changing saved sign-ins or preferences.

## Windows desktop lifecycle

Tray persistence defaults on; the floating widget defaults off. Closing the dashboard hides it only after tray initialization succeeds. Quit, operating-system shutdown, or closing with persistence disabled stops the whole app. A per-data-directory Windows mutex and activation event restore an existing instance on relaunch. Normal launch still shows the dashboard; automatic login startup is not configured. Mac, browser previews, saved reports and prerequisite diagnostics omit these controls. Basic native smoke checks bypass persistence.

The desktop controller separates lifecycle policy from a WinForms adapter using the existing pywebview/.NET runtime. Desktop preferences live in the existing settings table and apply independently of indexing jobs. The bridge exposes `desktop_state`, `desktop_settings`, `desktop_command` and `widget_summary`. Widget summaries share dashboard aggregation and cache by data revision, timezone and local date, polling every two seconds while visible. The separate widget build has no shared output chunks with the self-contained dashboard report.

The 240-CSS-pixel widget shows Today/All time, with tokens, API-equivalent cost and observed line changes selected initially; main chats are optional. Empty selection offers a Settings shortcut. Both columns include all enabled sources and ignore dashboard filters. The widget has no title bar or persistent footer. Its own bridge exposes widget_layout (measured CSS width, height and effective browser rendering scale) and widget_command (native drag, context menu or dismissal); these operations are scoped to the current widget instance. The native host rounds physical sizes up and deduplicates resize requests. Windows owns dragging, using native cursor coordinates rather than CSS screen coordinates. Right-click or Shift+F10 opens the native dashboard/settings/pin/hide menu. Clicking outside, activating another window or pressing Escape dismisses it. WebView2 mouse and keyboard events forward dismissal through the bridge, and native window deactivation closes the popup. Position corrections wait until a drag ends. Native positioning uses monitor work areas and remembers a version-2 physical monitor-relative position, accepting legacy DeviceDpi-relative positions on restore. Closing the widget disables it; its pin setting is persistent. The tray provides Open dashboard, Show/Hide widget, Settings, Refresh and Quit.

## Snapshot v1

`.codex-insights` is a ZIP containing exactly `manifest.json` and `facts.jsonl`. Manifest: format/version, app version, stable exporter UUID, monotonically increasing revision, label, creation time, fact count, SHA-256 of the decompressed facts, and conversation-content=false.

Each fact holds session/segment IDs, sanitized project identity/label, ancestry and immutable boundary metadata, model/tier/effort context, response token traces, timestamped prompt/assistant signatures, hashed edit files with counts/outcomes, activity timestamps and byte-prefix proofs. Prompts, responses, tool arguments, shell commands, patches, credentials and absolute paths are excluded. Export contains locally observed candidates only, so imported data is not circulated back as new local history. Full snapshots keep transfer logic simple.

Desktop and CLI exports share `snapshot_export.export_usage`: refresh enabled local sources, collect refresh errors and offline sources with retained candidates, then serialize v5 facts. The desktop runs this as one cancellable foreground job on the indexing queue. Completion results add `refresh` counters (`files`, `changed_files`, `bytes_read`, `errors`, `skipped_errors`, `offline_sources`) and a `warnings` string array. Sources retains the last completed export notice across live redraws. These local diagnostics never enter the snapshot. Cancellation is checked after refreshing and before atomic publication; revision advances only after publication. Missing unused default folders do not create warnings.

Claude profile location resolution is shared by history discovery and bridge setup. A private `claude_discovery_seen` setting tracks canonical roots, including explicit forget operations; migration treats the previously offered standard root as seen even when forgotten. New environment-configured roots are discovered on startup without resetting source inclusion. Claude ownership records and previous-command files are scoped by a hash of the canonical settings path, with legacy ownership migrated to the standard profile. Snapshot facts contain no profile locations or setup metadata.

## Packaging and validation

Windows portable folder zipped locally by PyInstaller after Python and frontend checks; the system supplies WebView2/.NET. Intel Mac exporter built locally on an Intel Mac with py2app using an x86_64 Python runtime, macOS 12 deployment target. Builds currently have no signing/notarization. Releases are uploaded manually after testing the extracted archive on the target computer. No automatic GitHub Actions build or publishing workflow.

`build_mac.sh` builds into a unique local directory and bundles `bridge_entry` as a py2app extra script. Frozen Mac setup locates it under `Contents/MacOS` from `RESOURCEPATH`, without treating the bundled Python interpreter as the bridge. Missing/non-executable helpers produce setup-only diagnostics. The build validates x86_64 executables and tests an extracted archive before producing release artifacts/checksums. Exporter native smoke requires the Mac Exporter heading, Sources cards, export control, an idle index and the Python bridge; dashboard smoke retains its chart requirement. Packaged transfer smoke uses only synthetic Claude facts and compares receiving-dashboard cost, cache discount and coverage.

The native UI loads before background indexing starts. A lightweight entry point records local startup diagnostics before importing the app and native dependencies, including failures during engine initialization. Windowed executables supply standard streams for dependencies that expect them. Native errors show a dialog with the local log location; `--diagnose` checks frontend/native prerequisites without reading sessions or opening a window.

Regression tests cover response counter resets/repeats, cached/reasoning subsets, append-only reads, partial lines, duplicates, disconnected roots, forgotten sources, full snapshot replacement, integrity failure, privacy, delayed edit confirmations, unknown prices, exact portable boundaries and late parent history. Browser smoke checks exercise navigation, filters, project search, chart switches, narrow windows and standalone exports. Demo data is synthetic and safe to publish.

## Limits and later options

Log formats can evolve; unsupported records and histories are exposed as coverage diagnostics. Observed edits remain partial for writes outside recognized patches. Cost estimates exclude non-token services. First-time indexing is proportional to raw history size; later refreshes are incremental. Source deletion is conservative: retained cached history requires explicit forgetting. No custom rate editor, automatic update service or delta-transfer protocol in v0.1. Those can be added when actual use justifies them.

## Dashboard token headline and widget disclosure

`account_totals.py` sums fetched `summary.lifetimeTokens` across enabled account connections, deduplicating known identities and choosing the freshest available counter per account. `accounts.token_total` and `dashboard.account_token_total` include account coverage and freshness without exposing identities. `indexed_tokens.py` adds `dashboard.indexed_token_totals`, containing nullable all-time totals, counter coverage and session counts per provider from the same SQLite snapshot as dashboard analytics. These counters use canonical enabled-source usage independently of dashboard filters.

The live dashboard Total tokens card adds the reported Codex lifetime sum to indexed Claude Code and Antigravity totals, with the filtered analyzed total beneath it and a provider breakdown in its help text. If no reported Codex counter exists, indexed Codex tokens substitute with an Indexed Codex fallback label. A reported zero never triggers fallback. Partial reported account totals do not mix with indexed Codex usage; unresolved identities remain labeled partial. Zero, missing, partial and stale totals stay distinct. Account polling updates the reported component without rebuilding charts; analytics revisions update indexed components. Total-processed text equivalents use the same combined headline total and refresh together on account polling, preserving the selected basis and expanded disclosure. Output-only equivalents use filtered recorded output and explicitly describe that scope. Missing components remain unavailable; partial and stale totals remain labeled. Widget metrics, charts, costs, images, demo/exporter modes and read-only reports stay analyzed. HTML reports omit the global provider totals as well as live account data.

`widget_details_expanded` defaults true and is stored with desktop preferences. A single Details toolbar button toggles the metrics region, retains keyboard focus, and restores state across launches. A grid/transform transition has reduced-motion support. Automatic sizing uses the optional bottom anchor in `widget_layout` to reveal details upward within monitor bounds. Custom height stays fixed while content scrolls. With account usage disabled, metrics remain visible so the widget cannot become blank.

## Widget height, presentation and controls

`widget_height_css_px` is nullable: null restores automatic sizing; finite numbers from 120 through 65536 are saved as preferred CSS-pixel height. Settings exposes Automatic/Custom and a numeric input. The native host applies the available monitor height as a display cap without changing the stored preference. `widget_layout.height` measures intrinsic content independently of the viewport. Fractional browser scale is converted with upward rounding, and the root border fits the integer browser viewport. The bridge adds `resize_top`, `resize_bottom` and `fit_content` widget commands, scoped to the current window generation. `widget_resize.py` samples native cursor coordinates on a GUI timer, preserves the opposite edge and width, suspends automatic geometry changes during a gesture, supports Escape cancellation, and saves only on completion.

Compact account presentation and numeric state cues are separate from dashboard cards. Each account has header refresh/navigation buttons and one update timestamp on its last reset-countdown row. Time formatting uses the response timezone; focusable tooltips provide full dates. Remaining allowance uses healthy (>20%), low (>10%–20%), and critical (≤10%) states, including an explicit Exhausted label at zero. Refresh errors retain cached Codex readings with a Stale label. `widget-controls.ts` keeps per-account pending/errors independent, deduplicates displayed account IDs, respects disabled fetching, and reuses `account_refresh` plus the normal summary read for Refresh all.

`widget-providers.ts` filters only the widget: a bucket must have a valid numeric remaining percentage or reported USD usage (zero is valid), and the reading must be less than eight days old. Stale buckets stay visible with `data-state="stale"`; a passed reset renders Awaiting reading without a percentage. Age-based staleness is also applied locally (five minutes for status-line readings, ten for `/usage`), so a disconnected summary request cannot freeze freshness. Shared dashboard/setup diagnostics and provider caches remain intact.

`claude-limits.ts` holds the pure helpers shared by the dashboard card (`provider-ui.ts`) and the widget: kind-based labels (`session`/`five_hour` → 5-hour limit, `weekly_all`/`seven_day` → Weekly limit, `weekly_scoped` → Weekly · scope), absolute reset text in the response timezone with countdowns, reading age and the fresh/stale/reset-passed state.

`desktop_command({command:"show_account",account_id})` activates the dashboard and publishes `desktop_state.account_request` with an increasing sequence and connection ID. The dashboard consumes each sequence once, opens Accounts, resolves grouped connections after its account read, and focuses the target heading. Removed connections show a brief explanation. Widget data/browser regressions and native demo checks cover expiration/recovery, metadata alignment, refresh failures, navigation, resize gestures, persistence and display scaling.

## Antigravity public integration

Antigravity has a separate public-step parser (version 2), keyed by conversation, step index and creation time. Nullable usage components remain portable in transfer v5; imports from v1-v4 remain supported. Rewrites reconcile observations rather than multiplying counters. Passive hooks provide sanitized metadata, with an encoded Windows launcher and ownership-preserving configuration upgrades.

`antigravity_usage_enabled`, `antigravity_usage_settings`, and `refresh_antigravity_usage` mirror the existing optional Claude checks. A shared bounded CLI runner invokes the version-gated official `agy -p /usage --output-format json`, with 300-second polling, a 30-second timeout and backoff capped at 1800 seconds. Demo/exporter modes cannot fetch. Dashboard and widget share `ProviderAllowance`; the newest successful official check or status-line file wins. Raw CLI responses and credentials are never stored. Encrypted archive collection is disabled; retained facts remain readable. See [provider integrations](provider-integrations.md).
